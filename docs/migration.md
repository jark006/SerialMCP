# 升级与兼容说明

本文记录调用方需要关注的兼容变化。当前参数和结果以 [工具手册](tools.md) 及 MCP `tools/list` 为准，安装与替换程序见 [README](../README.md)。

## 从 0.3 升级到 0.4

0.4 面向 Agent 重新组织交互与反馈，保留原有十四个工具，新增六个工具。升级后重新连接 MCP，刷新工具定义。

| 变化 | 调用方调整 |
| --- | --- |
| 默认 compact，只含一份 JSON 文本 | 需要 structuredContent 时传 `response_mode: "detailed"`；文本不再仅包含串口 data |
| 枚举结果为 `{"ports":[...]}` | 从 ports 读取列表 |
| 默认展示上限 8192 UTF-8 字节 | 检查 truncated，通过 serial_get_output 分页，或设置 output_limit；实际接收量仍由 max_bytes 控制 |
| run_command.clear_input 默认 false | 明确需要丢弃旧输入时传 true；POSIX 命令优先用 serial_exec |
| 匹配边界后保留尾部 | 后续读取可能立即得到已到达的数据；需要丢弃时清输入 |
| 同端口冲突立即 busy，不全局排队 | 等原操作完成再发送；不同端口可并行。多客户端显式指定 port |
| 新增 terminal/binary 模式 | 默认 terminal 保留文本编码；binary 默认 hex，拒绝隐式 Shell 交互 |
| 文件上限 64 MiB，接收不覆盖本地文件 | 使用新路径，大文件可在目标端分块后分次传输 |
| read.timed_out 仅表示整体 timeout | 静默结束看 stop_reason=idle，取消看 cancelled |

新增：serial_select、serial_exchange、serial_send_key、serial_exec、serial_cancel、serial_get_output，共二十个工具。

保留 Windows x64、默认 127.0.0.1:8765 和 /mcp，无需修改 MCP 地址。所有客户端仍共享活动端口、串口句柄和有限输出缓存。


## 0.4.1 实机兼容修正

- ZMODEM 接收兼容 lrzsz 的高位换行 0x8A，分批结束握手后保留终端提示符。
- 自动生成的文件命令在协议前后同步 Shell；新增 shell_ready、remote_exit_code。自定义 Shell 命令可设 shell_command=true；Bootloader 和手动协议保持 false。
- 工具探测检查文件执行权限，PATH 中存在但不可执行不再报告可用。
- 实机验证流程和限制见 [Linux 开发板验收](testing-linux.md)。

## 0.4.2 远端错误反馈

启用 Shell 同步的文件传输失败时，若已收到该命令的非零退出标记，错误中会包含远端退出码与诊断文本，且不再将远端命令失败当作串口故障。工具名称、参数与成功结果结构不变。

## 0.4.3 长命令与异常恢复

- exec 长命令通过短行变量重组，发送时收集回显，避免行长度限制及串口缓冲溢出。执行内容与子 Shell 隔离语义保持不变。
- Shell 模式的 ZMODEM 下载等待真实协议头，远端结束标记可提前终止无效协议读取。
- 协议取消不再误标为硬件断连；下载不存在文件时返回对应的远端错误，随后可继续操作串口。
- 新增 test_linux_recovery.py 实机验收脚本，不改板端系统工具权限。

## 0.4.4 接收拒绝时同步取消对端

ZMODEM 因多文件、大小限制等原因拒绝接收时，会实际发送取消序列，让对端发送程序退出；仅改变本地协议状态不会终止对端。工具错误同时保留原始拒绝原因和已取得的远端退出信息。接口参数和成功响应不变。

## 0.4.5 标准输入语义一致

- exec 的默认标准输入统一为 EOF，长短命令一致。需要从串口等待输入的交互程序请使用 run_command；显式管道及输入重定向仍有效。
- 超过 128 字节的文件传输启动命令保留原来的串口输入，不再继承包装脚本的输入。
- 成功结果结构和工具参数不变，测试脚本新增本地目标在接收过程中发生变化的竞态覆盖。

## 0.4.6 文件路径与命令行选项区分

自动生成的文件命令会保护以减号开头的相对文件路径，包括单独的 -，保持其文件名含义。文件路径及启动命令中的 NUL 现在返回参数错误，以免协议元数据或终端输入被截断。工具名称、参数与成功结果结构不变。

## 0.4.7 完成标记不受 Shell 环境干扰

内部标记显式使用标准 printf，避免被用户函数或别名接管。长命令通过系统标准路径启动辅助 Shell，同时保留用户原有 PATH；因此 PATH 不含 sh 时也能执行长命令。工具参数、默认值和结果结构不变。

## 0.4.8 内部求值绕过 eval 别名

内部使用 `command eval` 执行请求内容，避免登录 Shell 的 eval 别名接管短命令，使未执行的原命令返回替代命令的成功状态。exec 与启用 Shell 同步的文件传输共用此修正，工具参数、默认值和结果结构不变。

## 0.4.9 X/YMODEM 等待有效的数据包应答

发送数据包后，不再因额外 CRC 请求或无关字节立即重传；等待 ACK、NAK、连续 CAN 或响应超时，并限制每包累计忽略的无关字节为 4096。避免噪声快速耗尽 16 次重试并连续发送重复包。工具参数、默认超时和成功结果结构不变。
